# Build log

## Step 1: Settings, Redis connection, indexes

- **Settings in one file:** every number and name the project uses (Redis host, model name, vector dimension, similarity threshold 0.90, TTL, RRF k, top-k, index names and key prefixes) lives in `app/config.py`, so I change a value in one place instead of searching the code. The 0.90 threshold comes from my own measurements (my highest "trap" pair scored 0.841 and my lowest near-duplicate 0.933). Values can also be overridden with environment variables or a `.env` file.
- **Two indexes:** `idx:docs` (prefix `doc:`, text field `content`) holds the document chunks, and `idx:cache` (prefix `cache:`, text field `prompt`) holds cached questions. Both have an `embedding` vector field (HNSW, FLOAT32, 384 dimensions, COSINE). The prefix is what links stored hashes to their index.
- **Create only if missing:** `_ensure_index` first calls `FT.INFO`, and creates the index only if Redis says it doesn't exist (catching `ResponseError`, not every exception). My experiments dropped and recreated the index on every run, but here the cache has to survive restarts. I tested this by starting the app twice: the second start had no errors and both indexes were still there.
- **Gotchas:** the vector dimension must match the embedding model (384), `decode_responses=False` is needed so float32 bytes survive, and old test keys (`cache:1` from my experiments) had to be deleted because they matched the new `cache:` prefix.
